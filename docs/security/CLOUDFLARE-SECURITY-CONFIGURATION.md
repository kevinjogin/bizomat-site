# Cloudflare security configuration for kevos.com

No Cloudflare account access was available while preparing this. **Nothing in the Cloudflare dashboard was changed.** Each item below is marked by how it is known.

## Confirmed from outside (public requests, 23–24 October 2026)

| Setting | Observed |
|---|---|
| DNS | Nameservers `uma.ns.cloudflare.com` and `zac.ns.cloudflare.com`; site is proxied (responses carry `Server: cloudflare` and `CF-RAY`). |
| Certificate and HTTPS | Valid certificate; HTTPS works with TLS 1.2. |
| HSTS | `max-age=31536000; includeSubDomains` sent on pages. Not preloaded. |
| HTTP → HTTPS | **Not enforced for pages:** `http://kevos.com/about/` returns 200. |
| Minimum TLS | **TLS 1.0/1.1 accepted.** |
| `www.kevos.com` | Redirects 301 to `https://kevos.com`. |
| TRACE method | Returns 405. |
| Page security headers | CSP (hash-based), X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, COOP all present on pages and the 404 page. |
| DNSSEC | Not enabled (no DS record). |
| Email DNS | SPF and DMARC published (Proton); DKIM published for three Proton selectors; no CAA. |
| Workers.dev | `workers_dev = false` in `wrangler.toml`; preview hostnames get `X-Robots-Tag: noindex` from the Worker. |

## Recommended dashboard changes

All are available on the Free plan unless marked. Apply one at a time, then check the site.

| Priority | Change | Where | Notes |
|---|---|---|---|
| 1 | **Always Use HTTPS: On** | SSL/TLS → Edge Certificates | Fixes the plain-HTTP gap. No visible change for visitors already on HTTPS. |
| 1 | **Minimum TLS Version: 1.2** | SSL/TLS → Edge Certificates | Very old browsers lose access; all supported browsers are unaffected. |
| 1 | **SSL/TLS encryption mode: Full (strict)** if an origin is ever used | SSL/TLS → Overview | The site has no origin server today (Worker + assets), so this is a check, not a change. |
| 2 | **DNSSEC: Enable**, then add the DS record at the registrar | DNS → Settings | Do the registrar step promptly; a wrong DS record makes the domain unreachable. |
| 2 | **Security managed rules** (Cloudflare Free Managed Ruleset) | Security → WAF | Free plan includes a reduced managed ruleset; the full OWASP Core Ruleset needs Pro or higher. |
| 2 | **Bot Fight Mode: On** | Security → Bots | Test the contact form and assistant afterwards; turn off if legitimate submissions are challenged. Super Bot Fight Mode needs Pro or higher. |
| 2 | **Rate limiting rule** (one free rule) for `/api/*`, e.g. 30 requests per 10 seconds per IP, action Block for 10 seconds | Security → WAF → Rate limiting rules | Complements the Worker limits; start with *Log* if available. |
| 3 | **AI crawlers** | Security → Bots → AI Scrapers and Crawlers, and *Manage robots.txt* | A content-strategy decision: blocking reduces use of READOS in AI training but may also reduce visibility in AI answer engines. Search-engine crawlers are unaffected either way. Leave as is until decided. |
| 3 | **Browser Integrity Check: On** | Security → Settings | Usually on by default. |
| 3 | **Security level: Medium** | Security → Settings | Avoid *I'm Under Attack* except during an incident. |
| 3 | **CAA records** | DNS | Add only for the authorities Cloudflare currently uses for your edge certificates. |
| 3 | **Notifications** for DDoS attacks, origin errors, Workers errors and SSL expiry | Notifications | Free notifications cover the main events. |
| 3 | **HSTS preload** | SSL/TLS → Edge Certificates | Only after confirming every subdomain serves HTTPS permanently; hard to undo. |
| — | **Cloudflare Access** | Zero Trust | Not needed today: the site has no admin area. Use it if a staging or admin hostname is added. |

## Account-level recommendations (owner only)

- Cloudflare, GitHub, registrar and Proton accounts: hardware security keys or passkeys as the second factor, recovery codes stored offline, and a review of who has access.
- Cloudflare API tokens, if any are created for automation: scoped to the single zone and the minimum permissions, with an expiry date.
- Workers secrets (`TURNSTILE_SECRET_KEY`, and `STRIPE_WEBHOOK_SECRET` if used) remain in the Worker's encrypted secrets, never in `wrangler.toml` or the repository. The test `wrangler config binds the edge rate limiters and keeps secrets out` fails if a secret is written into `wrangler.toml`.
