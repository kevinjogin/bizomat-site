## 1. Summary

- **Most of this brief is already built.** The owner approved an earlier version of it with an audit on 19 Nov 2026. It
  was built and released on 20 Nov 2026 with every flag off (kevinjogin/bizomat-site#94, #95 and later; the engine in
  kevinjogin/bizomat-cad#19 to #22). The design is `docs/cad/README.md`.
- **Nobody uses the ERP module yet.** Checked live on 20 Nov 2026: `bizomat.ai/cad/` still answers 200 with CAD
  Automation's own page, `/cad/dashboard` sends people to CAD Automation's own sign-in, `/erp/cad` needs a BIZOMAT
  sign-in, the connector `/cad/mcp` answers 401, and the engine reports version `68e3c1f`. So `cad_in_erp` and
  `cad_redirect` are off, as the project status says.
- **What is left falls in four groups:**
  1. The module has **never run end to end with the flag on against the real engine**. Staging had no CAD machine, and
     staging is now retired.
  2. **Gaps in what is built** (section 5). The most important: the company's download setting does not apply to
     exports that an AI assistant makes through the connector.
  3. **Shared services that no module has yet**: one global search, comments on records and one audit log across the
     tools. These are platform work, not CAD work.
  4. **Parts the owner deferred or declined** (configure-to-order, a 3D viewer), and parts that need a new add-in
     release (materials and sub-assemblies in bills of materials, dimensions and tolerances from drawings).
- **Two rules of the brief conflict with standing owner decisions**: testing on staging (staging retired 20 Nov 2026)
  and separate worker machines (no new Machine without approval). Section 6 proposes how to meet their intent.

## 2. Audit (Part 1)

### 2.1 What CAD Automation does

| Item | Today |
| --- | --- |
| Purpose | Lets AI apps (Claude, ChatGPT and other MCP clients) build native SOLIDWORKS parts, assemblies and drawings in the person's own SOLIDWORKS |
| Path of a request | AI app, then the connector `bizomat.ai/cad/mcp` (31 tools), then the server's checks (sketch solver, OpenCascade prediction of each feature), then a queue, then the Companion on the person's Windows computer, then the add-in inside SOLIDWORKS, which makes real features |
| Inputs | Tool calls in the feature format (`docs/DOCUMENT.md` in bizomat-cad); STEP, IGES or Parasolid files up to 32 MB (upload link, then `sw_import`); standard parts |
| Outputs | Native `.SLDPRT`, `.SLDASM` and `.SLDDRW` files saved on the person's computer. Exports through the server: STEP, STL, IGES, Parasolid, native files, PDF, DWG, DXF and PNG previews, each kept one hour |
| Templates | The person's own SOLIDWORKS drawing template and BOM template. None are kept on the server |
| Parameters | SOLIDWORKS global variables and equations (`sw_set_parameter`, `sw_set_equation`) |
| Scripts and macros | No user scripts run anywhere on the server. The only macro is the product's own launcher macro, on the person's computer |
| Viewers | No 2D or 3D viewer in the browser. PNG previews and SOLIDWORKS screenshots come back in the AI app |
| Master copy | SOLIDWORKS on the person's computer. The server keeps no CAD document |

### 2.2 Stack and deployment

| Part | Stack | Where it runs |
| --- | --- | --- |
| Engine | Python (Starlette and FastAPI, MCP SDK), build123d and OpenCascade, a Node sketch solver, server-rendered pages with one script | Fly app `cados`, Amsterdam: one Machine, shared CPU, 2 vCPUs, 2 GB; volume `opensketch_data` 1 GB; deployed only by bizomat-cad's `deploy.yml` |
| Add-in and Companion | C#, .NET Framework 4.8, SOLIDWORKS 2022 interop; WiX MSI, development-signed 0.13.1 | The person's Windows computer |
| ERP module | Hono (server) and React (screen) in `apps/work`; tables in migration `0037_cad.sql` | Fly app `bizomat`, Sydney, the `work` Machine (512 MB) |

The ERP screen (`apps/work/src/client/system/cad/Cad.tsx`) is loaded only when someone opens it (`lazy()` in
`SystemApp.tsx`), and it has no 3D code. The ERP reaches the engine over Fly's private network
(`WORK_CAD_URL = http://cados.internal:8080`).

### 2.3 Authentication

- **Inside the ERP:** one BIZOMAT sign-in. The ERP calls the engine with a one-minute ES256 assertion, used once and
  bound to the method, path and body, naming the person, the company, the permissions and the limits
  (`apps/work/src/worker/cad/keys.ts`, `client.ts`; the engine's `erplink.verify`). No second sign-in.
- **Outside the ERP (today's live path):** the engine has its own accounts in its data folder, scrypt passwords, Google
  sign-in, Sign in with BIZOMAT (client `cad`), and its own 90-day session cookie. The AI connector's OAuth sign-in and
  consent pages use that session.
- **Mapping:** at each sync the ERP matches every CAD account to a BIZOMAT account by BIZOMAT id, else by an email both
  sides confirmed (`cad_accounts`, `apps/work/src/worker/cad/sync.ts`). Unclear ones go to a review list. Nothing is
  copied or deleted.

### 2.4 Data model

- The engine stores no projects, designs, parts, assemblies, revisions, templates or rules. It stores **computers,
  pairings, commands with their history, AI connections, upload links and exports**.
- Each of these has an owner (a person) and, since 20 Nov 2026, a `company` (column in `bridge.sqlite`, key in
  `mcp_oauth.json` and in each export's record). `NULL` means made before, or outside the ERP.
- Products, revisions, bills of materials and engineering documents live in the ERP (Release 1) and already belong to a
  company. The ERP's CAD tables (`cad_accounts`, `cad_runs`, `cad_document_sources`, `cad_bom_proposals`,
  `cad_review_tasks`) have `company_id NOT NULL` with foreign keys and indexes.

### 2.5 File storage

| What | Where | Limits |
| --- | --- | --- |
| SOLIDWORKS files | The person's own computer | None from BIZOMAT |
| Exports | Engine data folder (`artifacts.py`) | 128 MB a file, 256 MB in all, 32 files and 128 MB a person, one hour each; per company `storageMb` (128 MB by default) |
| Files waiting for import | Engine data folder (`uploads.py`) | 192 MB in all, 4 links a person, 32 MB a file |
| Command history | `bridge.sqlite` in the data folder | Grows with use |
| Installer | `/data/downloads/` on the engine's volume | 1.3 MB (0.13.1) |
| Exports saved to a product | ERP file store, as engineering documents | The ERP's engineering upload checks |

The volume's actual use was not measured from here (no Fly access in this session). The console's CAD Automation panel
shows each company's export storage once the module is on.

### 2.6 Compute

- **The CAD work itself runs in SOLIDWORKS on each person's computer**, not on BIZOMAT's servers.
- On the engine, the heavy checks (feature prediction, reading SOLIDWORKS' STEP output) run in separate worker processes,
  never in the web server (`cadworker.py`): at most 3 at a time, one kept for the owner, each replaced above 800 MB,
  stopped after 15 idle minutes.
- Jobs are commands in `bridge.sqlite` with a status, history, expiry and attempt count. They can be cancelled
  (`sw_cancel_command`). They are delivered at most once by command id. Automatic retries are deliberately not done:
  a model-changing command run twice would change the model twice.
- Timeouts: a tool waits 240 s by default, an import 600 s; per company at most 5 commands at once and 600 s each
  (changeable in the console).
- Measured on the owner's computer (15 Nov 2026): a fillet with its prediction took over 60 s; one status read took
  39 s. AI apps that end a tool call after 60 s stop `sw_selftest` part way (bizomat-cad `docs/KEVOS-TEST-REPORT.md`).

### 2.8 External CAD software

SOLIDWORKS only (2022 interop; run on SOLIDWORKS 2022 SP5 on the owner's computer, 15 Nov 2026). AI apps: Claude was
used in that run; ChatGPT and Grok connectors are untested.

### 2.9 Security

- **Uploads:** per-person links with size caps, filename checks and an expiry. The server does not parse them: it passes
  the bytes to the person's own SOLIDWORKS. They are not scanned for malware (the engine's `docs/ERP-MODULE.md` says
  so).
- **Parsing:** the STEP files that SOLIDWORKS sends back are read only inside the worker processes, so a bad file can
  stop a worker, not the server.
- **Scripts:** none from users run on the server, so the brief's script sandbox has nothing to hold.
- **Commands:** signed by the gateway and checked by the Companion; each computer signs its requests with a key it cannot
  export; deletes need the person's approval inside SOLIDWORKS.
- **Pages:** a Content Security Policy on every engine page; no tokens in the ERP (it keeps neither the private address
  nor the add-in key).
- **Malware scanning that exists:** ClamAV on `cados` for verification documents only (`evidencescan.py`, flag
  `evidence_scanning`, off).

## 5. Gaps in what is built

| Id | Gap | Where | Weight |
| --- | --- | --- | --- |
| G1 | Never run end to end with `cad_in_erp` on against the real engine. Staging had no CAD machine ("not reachable" there), and production has never had the flag on | `docs/cad/README.md`, "How the ERP and CAD Automation trust each other" | High |
| G2 | The company's download setting (managers and employees) applies only to downloads through the ERP. An AI assistant's `sw_export` returns a signed one-hour link (`/cad/mcp/artifacts/...`) whatever the setting, and that download is not in the company's history. The sync tells the engine which companies a person works in, not their permissions | engine `artifacts.py`, `sw_tools.py`; ERP `cad/sync.ts` | High |
| G3 | A read-only member gets no company in the sync, so their AI assistant works by person, outside the company, rather than being refused inside it | ERP `cad/access.ts` `cadCompanies`, `cad/sync.ts` | Low, a decision |
| G4 | The console's queue length is always 0; waiting commands are counted as running | engine `erplink.py` (`"queued": 0`) | Low |
| G5 | Notices only for failed runs; none for a review request (the review task has no assignee) or a released revision | ERP `cad/sync.ts`, `cad/routes.ts` | Medium |
| G6 | If the ERP's answer is older than 15 minutes, the engine works by person: company limits and team views lapse and nobody is told. No data crosses companies | engine `erplink.FRESH` | Medium |
| G7 | The engine keeps its own accounts, session and password sign-in (`/cad/login?password=1`) | engine `accounts.py`, `auth.py` | Medium, a decision |
| G8 | The engine's `company` is nullable; the brief asks for NOT NULL | engine `devicebridge.py`, `mcp_oauth.json` | Low: nullable is how rollback works |
| G9 | Exports on the engine are not kept under company folders; each export's record names its company and every read checks it | engine `artifacts.py` | Low |
| G10 | Bills of materials read top-level components only, without materials or sub-assemblies | add-in, `docs/cad/README.md` | Medium, needs an add-in release |
| G11 | Inspection plans show drawings but cannot take dimensions and tolerances from them (`sw_get_drawing` counts dimensions, it does not read their values) | add-in, ERP Quality | Medium, needs an add-in release |
| G12 | Uploads sent to SOLIDWORKS are not scanned | engine `uploads.py` | Medium |
| G13 | No thumbnails or 3D preview on product pages (the owner declined a viewer) | none | Low |

Permission matrix differences from the brief (built that way on 19 and 20 Nov):

- Employees see their own CAD history by default (scope `own`); the brief gives every role "view designs". Approved
  drawings are seen in Products and Engineering under its own rules, so employees still see the designs themselves.
- "Release or approve a revision" follows the ERP's engineering approver with segregation of duties, not the company
  role.
- "Delete designs" maps to removing other people's computers and AI assistants (owner and admin). There are no design
  records in CAD Automation to delete.

## 7. Recommended approach

1. **Decisions** (no code): the owner accepts section 6, chooses the pilot company and answers section 10.
2. **Close the small gaps**, one pull request in each repository, behind the existing flags, no new service, secret or
   Machine: G2 (the sync carries each person's download permission per company; `sw_export` then keeps the file without
   a link where downloads are not allowed, and every link download is recorded as a run), G4, G5 (a notice to the
   person asked to review, and to the requester when a revision is released), G6 (a warning in the console and on the
   module when the sync is late), and G3 as decided. Each with tests.
3. **Local end-to-end run** with the flag on: the real engine (`apps/cad`), the real work app, a stand-in Companion.
   Part 9 tests 1 to 8, 13 and 15, written up as the security and migration test results.
4. **Production pilot** (with the owner's approval): `cad_in_erp`, and `company_members_v2` for the same company, on for
   the pilot company only. The owner pairs their own computer through the ERP and runs one real job. Rollback is
   switching the flag off.
5. **Wider rollout**, then `cad_redirect` (owner's approval).
6. **Later, as separate briefs:** materials, sub-assemblies, dimensions and tolerances (G10, G11; an add-in release
   0.14 with signing and a new installer); scanning uploads with the existing ClamAV (G12; memory permitting); the
   platform's global search, comments and one audit log for every module; retiring the engine's password sign-in once
   every account is mapped (G7).

## 8. Risks

| Risk | Note |
| --- | --- |
| The module is unproven end to end | G1; steps 3 and 4 above |
| Design files cannot be fully controlled | The master copies are on people's own computers. The download permission protects only files that pass through BIZOMAT. Never promise that designs cannot leave a company |
| Memory on `cados` (2 GB) | Three CAD workers of up to 800 MB each, and ClamAV up to 1 GB while it scans. More scanning would compete with CAD work |
| Distance | The ERP is in Sydney and the engine in Amsterdam; an open CAD screen asks the engine every 15 s. Acceptable for a pilot |
| AI apps' 60 s tool limit | Long jobs (self test, slow fillets) can be cut off by the AI app; known, listed in bizomat-cad's next steps |
| Silent fallback | G6 |
| Public repositories | This audit and the design are readable by anyone. They hold no secrets |
